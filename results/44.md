Assume the SPA and API share one HTTPS origin and revocation must apply at the next authorization check. Use opaque server-managed sessions: signature/expiry checks alone leave stolen JWTs usable for 30 days.

- Generate a random 32-byte session ID after login. Set `__Host-session` with `Secure; HttpOnly; SameSite=Lax; Path=/`, without `Domain`. Store its SHA-256 digest alongside user ID, user version, creation/last-activity timestamps, absolute expiry, and revocation status in a shared database. Regenerate the ID after authentication and privilege elevation.
- Enforce 24-hour idle and 30-day absolute expiry server-side; use shorter admin sessions and recent MFA for sensitive actions. No browser-readable access or refresh tokens are needed.
- Each protected request reads authoritative session/user state, checks expiration, revocation, disabled status, and matching `auth_version`, then enforces current permissions and ownership. Avoid stale authorization caches; fail closed during store outages. Invalid sessions receive 401; insufficient permissions receive 403.
- Logout revokes one session and clears its cookie. “Sign out all devices” atomically increments the user's version; future login remains possible. “Disable user” atomically disables the account and increments its version, preventing new sessions. Session creation must check enabled status transactionally. Audit actor, target, time, and outcome without credentials.
- Revocation succeeds after durable commit. Subsequent authorization checks reject old sessions across instances. Already-authorized requests may finish; sensitive writes must serialize their final authorization check with revocation. Recheck long-lived connections per privileged action.
- Require CSRF tokens and Origin validation for state-changing requests, including login/logout; keep GET read-only. HttpOnly limits credential theft, but XSS can still perform authenticated actions. Fix injection sinks, sanitize necessary HTML, and deploy restrictive CSP.

At cutover, reject legacy JWT authentication on every API and require reauthentication; clearing localStorage cannot invalidate stolen tokens.
