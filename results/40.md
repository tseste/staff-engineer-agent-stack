Assume existing HTTP instrumentation uses OpenTelemetry; checkout awaits one queued job; each delivery contains one message. Reuse the current collector/backend. These are proposed changes, not executed work.

1. Add a `checkout.publish` PRODUCER span around enqueue. Inject W3C `traceparent` and approved `tracestate` into message metadata while this span is active. Disable baggage propagation. Preserve context through delivery and redelivery.
2. Extract context into a clean worker context; start `checkout.process` CONSUMER with that remote parent. Detach context and end spans in `finally`. Missing/invalid context starts a new trace without failing processing. Redeliveries get separate spans and attempt numbers; republished retries inject their new producer context. Future batches need per-message spans or links.
3. Instrument payment HTTP calls as CLIENT spans with safe status and timeout category. Provider internals remain invisible; external trace-header propagation requires an agreed integration. Expected ancestry: frontend → gateway → checkout → publish → process → payment client. Worker spans may outlive the frontend deadline.
4. Record queue age from broker enqueue time, documenting clock uncertainty; processing and payment durations come from their spans. Add deadline/cancellation events at callers and workers. Inspect the timeline to separate queue delay, worker work, and payment latency. Do not sum overlapping spans or equate frontend timeout with failed payment.
5. Replace email/card logging at source with allowlisted fields: trace ID, span ID, opaque job ID, operation, attempt, outcome, sanitized error type. Disable raw exception/body/header capture. Apply collector redaction defensively; restrict existing sensitive logs pending retention review.

Verification: use synthetic jobs with 100% sampling. Inject queue delay, payment delay/timeout, and redelivery. Assert ancestry, distinct retry spans, concurrent-job context isolation, and worker completion after frontend timeout. Scan exported traces/logs for seeded email/card canaries: zero occurrences. Verify malformed context still processes. Compare controlled latency/CPU with tracing enabled/disabled.

Production: batched export and parent-based 1% head sampling initially. Unsampled errors cannot be recovered; use independent timeout/error metrics for incidence.
