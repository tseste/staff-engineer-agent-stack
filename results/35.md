# Postmortem: export failures following deployment

**Status:** Draft. **Impact:** Exports failed for 40 minutes following a deployment. The number of affected exports and customers, retry outcomes, and any data loss are unknown.

The change was merged after green CI. CI omitted queue protocol tests, staging used an older worker, and rollback instructions were stale. Release checks therefore did not establish compatibility with the production worker configuration, and recovery guidance was unreliable.

**Causal assessment:** The deployment triggered the failures. Queue protocol incompatibility is a working hypothesis requiring confirmation from the change, deployed versions, and failed messages. The established weaknesses are missing protocol coverage, staging drift, and stale recovery guidance. The engineer’s seniority is not a root cause; release safeguards should support reliance on green CI.

**Known sequence:** Green CI → merge → deployment → 40-minute failure window. Detection time and recovery method are unknown. Any delay attributable to stale rollback instructions remains unverified.

Owners and deadlines below are proposals, measured from this draft.

1. **P0 — Gate releases on queue compatibility.** Owner: export service lead. Due: before the next export release. Add an incident regression and CI integration tests using actual producers/workers across supported upgrade and rollback combinations, including queued messages. Acceptance: the regression fails on the faulty version and passes on the fix; incompatible combinations block release.
2. **P1 — Repair and exercise rollback.** Owner: on-call lead. Due: three working days. Update version selection, component ordering, queued-message handling, and recovery verification. Acceptance: another engineer follows the runbook in a controlled rehearsal and demonstrates successful export completion after rollback.
3. **P1 — Enforce staging version parity.** Owner: release engineering lead. Due: seven working days. Pin intended release artifacts and automatically check worker versions. Acceptance: deliberate version drift blocks promotion, and an end-to-end export passes with the intended deployment combination.

Track these actions and review completion evidence weekly.

The protocol mechanism and recovery-delay hypothesis require evidence.
