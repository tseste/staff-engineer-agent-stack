Assumptions: each customer is one tenant; users may hold multiple tenant memberships. “Isolation” has no specified contractual boundary. Proposed enterprise promise: a dedicated application/data stack with shared administrative control; product and security owners must validate this scope before commitment.

Recommend hybrid tenancy. Keep 95 customers pooled at existing prices. The architecture owner chooses enterprise isolation over fleet-wide silos, which multiply operating cost; schema-per-tenant alone cannot deliver the proposed boundary.

| Resource | Small customers | Enterprise |
|---|---|---|
| PostgreSQL | Shared tenant-keyed tables | Dedicated instance and credentials |
| Compute, workers, queues | Shared, tenant-scoped quotas | Dedicated |
| Objects, caches, search, analytics | Tenant-scoped namespaces/access | Dedicated destinations |
| Keys, backups | Scoped access; documented shared recovery boundary | Dedicated keys and backups |

Platform owns provisioning and upgrades. Finance must price incremental enterprise infrastructure/support against measured costs; do not subsidize it through small-customer increases or claim savings without evidence.

Immediate priorities, before migration:

1. Security and backend owners disable affected exports/support operations until tenant scope is enforced. Treat omissions as potential exposure: preserve audit evidence, determine affected artifacts/access, and invoke incident response if warranted.
2. Resolve tenant context from authenticated membership or explicitly authorized support sessions. Require it in every query, job payload, artifact, download, and retry; reject absent or conflicting context. Use tenant-scoped support grants with expiry and audit.
3. Add PostgreSQL row-level security as defense in depth, with non-owner/non-bypass runtime roles and transaction-scoped tenant context. Verify connection reuse, joins, exports, retries, and support access using cross-tenant negative tests before re-enabling paths.

Control plane owns stable tenant IDs, membership authority, placement, lifecycle, and versioned entitlements. Application services enforce that state; unknown placement/context fails closed. Billing owns invoices; deduplicated tenant usage feeds billing, never authorizes access.

Lifecycle: provisioning → active → suspended → deleting → deleted. Platform uses idempotent operations and reconciled status; failures remain pending/failed. Migration engineering owns enterprise reconciliation, cutover, and rollback. Data/privacy owners verify tenant export, restore, and deletion across derived stores/backups. Operations measures tenant latency, queue fairness, and cost. Revisit placement after isolation commitments, recovery failures, or measured noisy-neighbor breaches.
