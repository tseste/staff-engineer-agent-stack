# Delegation plan

Assumptions: The shared token fixture makes auth refresh and billing potentially coupled; a common root cause is unproven. The CSS failure is independent as stated. Actual file paths, failure output, and test commands must come from the repository when available. This plan launches no agents.

## Task A — Auth, billing, and token fixture

Assign one agent exclusive ownership of the shared token fixture, both failing tests, and narrowly necessary auth/billing implementation changes. Investigate the two failures together before proposing separate fixes. Determine whether fixture validity, expiry, mutation, or cleanup explains either failure; preserve intended authentication and billing behavior.

Provide a self-contained packet containing both test names, assertions and failure output, fixture setup/teardown, relevant consumers, expected token behavior, and the exact permitted files. Do not provide unrelated session history. Require a root-cause explanation distinguishing evidence from hypotheses, changed-file list, patch, validation results, and remaining uncertainties. Do not weaken assertions merely to pass tests.

## Task B — CSS layout

Assign a second agent exclusive ownership of the failing layout test and its relevant component/styles. Provide its assertion and failure output, expected layout, viewport/browser settings, relevant source, and permitted files. Require the same evidence and patch handoff, plus a visual check at the failing viewport and relevant responsive sizes. Exclude token fixtures and auth/billing code from its scope.

These two tasks may run concurrently in isolated checkouts with independent test resources. Shared configuration, dependencies, global styles affecting other domains, or newly discovered overlap require coordinator review before edits; serialize affected work if independence no longer holds.

## Coordinator ownership and integration

The coordinator owns scope changes and integration. Review both explanations and diffs for overlapping edits, hidden dependencies, assertion weakening, and unrelated changes. Apply the patches to one integration checkout.

Validate auth and billing individually, together, and in reversed order where supported to detect fixture state leakage. Run other token-fixture consumers. Verify the CSS failure and adjacent layout behavior. Then run the full relevant project suite on the combined changes. Resolve failures before acceptance and record any checks the environment prevents. Agent reports alone do not establish successful integration.

## Skill guidance and limitations

Applied the skill’s independent-domain boundary, grouping of related failures, isolated self-contained task context, explicit scope and handoff requirements, and review/conflict/full-suite checks. Three failures produce two ownership groups because two share state. No repository was supplied, so these are proposed actions; no causes, patches, or test results are claimed.
