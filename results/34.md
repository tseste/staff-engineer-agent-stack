# Checkout incident: minutes 0–15

Owner: Checkout on-call. Last verified: unverified draft. Clock starts at detection.

Assumptions: responders have incident access; disabling the flag selects the previous discount behavior; propagation takes ≤2 minutes. Verify these before changing it. Thresholds below are proposed.

1. **0–2 minutes — Declare and bound impact.** Declare provisional SEV2 (major degradation); assign commander, operator, and separate communicator. Page checkout/release owners. Freeze deployments. Record release ID, onset, errors/attempts, traffic volume, affected regions and discount cohorts; attach dashboard/log links. Initial notice: “Checkout errors rose from 0.2% to 18% after release; database healthy; investigating discount path; next update at minute 15.” Temporal correlation is a hypothesis.

2. **2–4 minutes — Disable new discount path.** Confirm production environment, exact flag, polarity, targeting overrides, previous value, and fallback pricing behavior. Set the flag to disable the new path for all affected traffic; record operator/time/change ID. Verify effective evaluations across instances/regions and disappearance of new-path traces. Prepare the known-good release and check rollback compatibility concurrently. Leave the healthy database unchanged.

3. **4–6 minutes — Decide.** If propagation exceeds two minutes, the flag cannot be changed, or errors worsen, initiate rollback immediately once compatibility is confirmed. Otherwise compare post-propagation errors with baseline. If still above 0.3% at minute 6, initiate rollback; if ≤0.3%, continue verification. Rollback takes 20 minutes: a minute-6 start finishes around minute 26, beyond this runbook. Escalate immediately if rollback is unsafe or unavailable; keep incident ownership explicit.

4. **6–12 minutes — Prove recovery.** Require five consecutive post-propagation one-minute windows at ≤0.3% errors with representative traffic, including previously affected cohorts; low volume or missing telemetry means unproven. Check latency against pre-release levels. Run approved synthetic checkouts with/without discounts; verify expected prices, successful order/payment records, and no duplicate charges. Save timestamps, numerator/denominator, dashboard snapshots, flag evaluations, and test IDs.

5. **12–15 minutes — Communicate and hand off.** If every gate passes, enter monitoring with flag disabled. Otherwise remain mitigating, escalate to engineering leadership, and report rollback progress/ETA. Publish measured impact, outstanding failures, owner, and next update at minute 30. Schedule postmortem and review this runbook before reuse.

Skill guidance used: the service-outage template’s impact assessment, recent-change triage, feature-flag mitigation, rollback escape hatch, verification, escalation, and communication; the main skill’s numbered checklist, explicit assumptions, ownership, and verification metadata.

Limitations: no commands were executed and no recovery was observed. Actual flag identity, dashboard links, access, compatibility, propagation time, traffic sufficiency, and acceptable error/latency thresholds require service-specific validation. The 0.3% gate is a proposed operational tolerance around the supplied 0.2% baseline.
