Assume an external provider supports signed payloads, signed delivery timestamps, and stable event IDs; delivery is at least once. Controls are proposed and unverified.

| Threat | Practical preventive controls | Verification |
|---|---|---|
| Forged events | Application: verify the provider’s signature over exact raw bytes and signed timestamp using its documented scheme before parsing or processing. Use constant-time MAC comparison, protected per-provider secrets, rotation, and authenticated tenant/event-type authorization. Require HTTPS. | Missing/invalid signatures, altered bytes, wrong keys, and unauthorized tenants cause no side effects. |
| Replayed valid events | Application: enforce signed timestamp freshness, including future skew; start with a five-minute tolerance only if compatible with provider retry semantics. Maintain durable deduplication using authenticated provider/account/event ID; retain records across the supported redelivery horizon, longer for irreversible effects. | Expired signatures fail; replay within the freshness window cannot repeat an effect. |
| Duplicate delivery | Application/data: atomically insert a unique event key and business changes in one transaction. Acknowledge only after durable acceptance. Use a transactional outbox and downstream idempotency keys for external effects; retry unfinished work and acknowledge known duplicates successfully. | Concurrent duplicates, worker crashes, and lost acknowledgments produce one committed business effect and recover unfinished work. |
| Payload-driven SQL injection | Application/data: bind all SQL values with parameterized queries; allowlist dynamic identifiers. Enforce payload schemas and size limits. Restrict database privileges. Signed content still requires these controls. | SQL metacharacters remain data through every query path; malformed payloads fail validation. |

A VPN restricts network reachability and encrypts its tunnel. It does not validate event signatures, freshness, uniqueness, or SQL construction; any permitted or compromised peer can still exercise those weaknesses. Providers may lack VPN support, breaking delivery. Prefer public HTTPS ingress with these controls and private workers/database; provider IP allowlisting is supplementary.

Prioritize signature verification, parameterization, and durable idempotency. Add detective counters/alerts for signature failures, stale timestamps, duplicates, validation failures, and processing failures; exclude secrets/raw payloads from logs. Corrective runbooks should cover key revocation/rotation, retrying durable unfinished work, and reconciling incorrect effects. Review retention, provider signing changes, and recovery tests regularly.
